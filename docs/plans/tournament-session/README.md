## 2. 已确认需求与默认决策

| ID | 用户确认 | 必须落地的行为 |
|---|---|---|
| R01 | 关闭熟人记牌，但保留功能 | 默认关闭，保留后端实现和历史数据，提供高级设置中的重新启用入口 |
| R02 | 每手自动跟踪位置和筹码 | 同一牌桌持续存在；固定我的座位，逐手推进位置；承接上一手确认的余额 |
| R03 | 每手结束，所有人筹码可手动重设 | 全桌结算表可编辑最终实际余额，确认后作为下一手起始筹码 |
| R04 | 主要用于锦标赛 | 支持人数减少、转桌加入、淘汰、升盲及最终单挑；现金桌补买不属于本次核心范围 |
| R05 | 连续记录每手 | 正常流程每手都记录；不以跳过手牌为默认入口；自动手数与庄位同步 |
| R06 | 采用直接改实际余额的结算方式 | 不要求输入所有对手底牌、赢家或手动分配边池；人工最终余额有最终权威 |
| R07 | 其余按建议设计 | BB优先显示、同时显示实际筹码；支持固定座位管理、人员变更、位置校准、本地恢复 |
| R08 | UI隐藏熟人训练，不占布局；牌桌体现第几手 | 关闭功能的整个区域退出布局；牌桌标题常驻本桌手数、当前阶段与我的位置 |
| R09 | 实际更多用于锦标赛进行中的实时推演 | 以快速逐手录入为主路径，设置与学习内容降级；推演只呈现与最新录入局面匹配的结果 |

产品主场景明确为“锦标赛逐手记录与实时局面推演”，复盘是同一份记录的后续用途。本期“实时”指用户录入动作后计算当前局面，不代表自动识别现场、自动知道对手底牌或代替用户操作对局。这里沿用人工逐手输入方式，不另做一套会混写会话的“实战/模拟”状态机。UI详细约束见5.1–5.7。

以下是为消除歧义而确定的产品默认值，实施时不需要反复询问：

- 初建桌可选6/8/9个物理座位；内部支持容量2–9。实际入局人数独立于容量，支持2–9人。
- 桌上按固定座位号1…capacity顺时针排列。你绑定一个固定座位上的本次入座者，BTN/SB/BB随手变化。
- 初始筹码/每人筹码可以切换“BB输入”和“筹码输入”；金额存储始终为整数筹码，默认BB输入。已确认余额不因为显示单位改变而改写。
- 正常无人进出时自动轮转。人员变化时显示位置预览并要求确认一次；提供庄位/盲位校准，现场位置是最终依据。
- 不自动猜测未知摊牌输赢。真实余额无法推断时显示“待核对”，由用户填写或确认最终实际余额。
- 关闭熟人功能时，具名统计和共享人群学习均不读、不写、不参与建议；基础位置范围、当手动作推断、权益/CFR/ICM保留。
- 前注本次沿用“每位玩家前注”语义，明确标注；支持0。大盲前注BBA、升盲倒计时和现金桌补买作为后续独立需求，不把现有ante字段擅自改成BBA。
- 本次本地保存一个当前牌桌会话及可恢复的当前手；不实现云端账号、跨设备同步、数据库牌谱检索或自动识别真实牌桌。
- 对手暂时离开座位、但仍在赛事中：保留其座位和筹码，照实际规则录入动作；不能把“暂离”自动等同移除玩家或不扣盲。本期不自动判其弃牌。

## 4. 用户主流程

### 4.1 创建牌桌：只做一次

用户依次选择物理座位容量、有人座位、我的座位、当前庄位，输入小盲/大盲/每人前注及每人起始筹码。系统展示位置预览和每人的筹码/BB，确认后创建第1手。

“统一初始筹码”仅作为批量预填：例如100/200盲注，统一50BB产生每人10000筹码。单独改某人不影响其他人。开始后不再在页面顶部放置会把整桌恢复默认的“起始筹码”输入。

可选ICM仅在用户明确设置“决赛桌/桌上包括全部剩余选手”时启用。默认无ICM。熟人记牌默认关闭。

### 4.2 本手进行中

顶部显示“第N手 · 你：5号座/CO · 盲注100/200 · 每人前注25”。牌桌固定物理座位，角色徽标移动，玩家和筹码不跟着角色交换。

选择自己的底牌后沿用现有动作录入。所有人的本手剩余筹码与投入自动更新。英雄弃牌后仍能录入其余玩家，不结束整个牌桌。全下0筹码在本手中是全下，不是已淘汰。

本手身份、座位、起始筹码、盲注和奖金快照冻结。相关编辑通过“下一手设置”形成草稿；不能修改已录入牌谱的计算基准。底牌纠错/动作撤销走本手修订流程。

### 4.3 本手结束，核对全桌余额

操作台进入“核对本手结束筹码”。表格按固定座位排列，展示座位、你/对手、手前筹码、本手投入、可用的确定结果、最终实际余额、差额和BB。

- 已知无摊牌获胜：可以预填可证明的结算余额，用户仍可修改。
- 未知摊牌：胜负涉及的余额显示待核对，不预填虚构模拟赢家。已知弃牌者的余额可以预填。
- 所有人都可直接重设最终余额。输入0后，在确认页标注将淘汰；不在输入过程中立即删座位。
- 未变动/已正确的余额可以一键“确认当前填写值”，不要求每个框重新输入；仍未知的行必须先补齐。
- 显示总筹码核对；无人员变化时总额应守恒。允许实际纠错导致总额变化，但必须填写原因并显式确认差异，不能静默吞掉差额。

用户按“确认余额，进入下一手”，余额保存并轮转一次。新手沿用全部已确认设置，只需要选新底牌、继续录动作。

### 4.4 人员变化

结算页分成先后两个步骤：先确认刚结束这手的所有入局者余额，再编辑下一手座位。离桌者仍必须留在刚结束这手的结算表里。

淘汰=最终余额0；转走=余额可能大于0但不再坐本桌；新入座=在空座输入新玩家筹码并生成新occupantId；换人=结束旧occupant再创建新occupant。每次变化显示即将入局的人数、你的新位置及BTN/SB/BB。

多人淘汰、空庄位、转成单挑不得简单压缩数组后循环BTN。处理按契约中的位置规则；无法根据现有信息确定现场盲位时，停在预览并要求校准，不能假装已精确自动跟踪。

### 4.5 升盲与恢复

升盲通过下一手设置生效：实际筹码10000在BB200时为50BB，BB400时为25BB；筹码余额仍10000。结算表的BB换算一直使用刚结束本手的BB，下一手预览使用新BB，标题明确两者。

刷新恢复当前会话、当前手快照、动作、结算草稿和手数；重新回放，避免使用过期缓存。首次打开若有会话，提供“继续当前牌桌”和“新建牌桌”，不自动清空。

## 5. 页面与交互交付要求

复用现有样式，不迁移React/Vue，不引入新的组件系统。新模块仍采用原生JS、静态HTML/CSS、FastAPI/PokerKit。

| 区域 | 必须具备 | 状态要求 |
|---|---|---|
| 会话栏 | 当前手数、固定座位、角色、盲注、保存状态 | 主按钮随准备/进行/结算阶段改变，不出现两个意义相同的“重开” |
| 筹码编辑 | 单位切换、双单位预览、全部余额 | 输入中保留焦点和光标；提交时校验，空字符串不能自动变0 |
| 牌桌 | 固定座位、空位、你、BTN/SB/BB、剩余筹码 | 小屏不横向溢出，固定座位布局不随人数突变；徽标不可遮住数字 |
| 结算面板 | 全桌余额、未知提示、差额、成员调整 | 待确认/无效/保存失败时禁用下一手；错误显示在对应行 |
| 位置预览 | 下一手角色、轮转方向、手动校准 | 人员变化时必须经过预览；确认重复点击不得多转一手 |
| 高级设置 | 熟人记牌开关默认关闭、ICM和下一手盲注 | 切换开关只影响下一手，历史数据不会被删除 |
| 操作记录 | 本手动作撤销、重录本手、手工结束进入结算 | 重录不移动BTN、不改变已确认余额；手工结束要求说明记录不完整 |

“跳过一手”不放在常规流程。允许“结束本手，手动核对余额”：用户提前弃牌或缺少完整后续动作时仍可保持逐手记录，产生一条标记为不完整的手牌；它仍需全桌实际余额与位置确认，不是静默跳过。

结束牌桌/覆盖现有会话是破坏性动作，应有清晰确认。常规下一手不增加多余确认弹窗；一张结算表完成余额和下一手变更的确认。

### 5.1 信息优先级与视觉延续

延续现有深绿牌桌、奶油牌面和金色强调，复用style.css变量。此次重点调整信息层级与操作密度。将高大的品牌页头收成紧凑栏；标题副文案用“锦标赛逐手记录 · 位置与筹码追踪”，去掉默认的“对手画像”卖点。首屏按以下优先级排布：

1. 当前第几手、阶段、轮到谁，以及你的位置/筹码。
2. 牌桌、公共牌、底池、录入当前玩家动作。
3. 轮到你时的当前局面推演摘要。
4. 按需展开的详细分析、动作历史、下一手设置、帮助。

术语统一为“本桌第N手”“录入动作”“局面推演”“核对实际筹码”。界面帮助说明结果基于已录入信息；不用“实测胜率”“真实赢家”形容范围推演。现有help-panel关于占位对手牌自动亮出、自动真实分池的描述需同步改写，文案与C03的结算可信度一致。页头、帮助和页脚的产品用途说明一并核对，统一为逐手记录与局面推演，不再仅写成赛后复盘；不在用途文案中作未经核实的平台规则概括。

### 5.2 隐藏熟人训练必须释放空间

关闭时，整块learn-panel、对手代号标题及names-grid、学习进度、统计清空入口、画像说明均从可视布局及键盘焦点顺序移除。DOM可以保留以供重新启用，但不能仅opacity:0、visibility:hidden或隐藏内部文字：这些方式会留下空白面板或间距。

父级grid/flex不得保留专用空行、固定高度和多余分隔线。不展示“学习功能已关闭”占位卡。唯一入口放“更多设置 → 熟人记牌”，保留开关及简短说明。按本手/下一手开关边界生效，后台请求门控遵循第6节。首次载入默认即隐藏，避免JS初始化前闪现。开启后采用折叠区域，不把常用操作挤到下方。

### 5.3 牌桌手数、阶段和金额

牌桌panel内新增独立标题行，示意：

```text
本桌第 12 手 · 翻牌                    已保存
你：5号座 / CO       盲注100/200 · 每人前注25
```

手数取Session.handNumber，不能用ops.length、接口调用次数或recentHands.length计算。它表示本会话从建桌起记录的手数，不是赛事官方累计手数；新建桌从1开始。牌桌标题在准备/进行/结算三态均存在，进入结算仍显示本手编号；仅下一手原子保存成功后增加。撤销、重录、刷新都不增加。

阶段用“待选底牌/翻前/翻牌/转牌/河牌/待核对筹码”，结束后显示“本桌已结束”；引擎street只决定进行中的街道名。手数与阶段不能叠在公共牌、底池或品牌水印上。小屏顶部可固定简短状态条，但不同时堆两个大标题；同一手数来自同一渲染来源。

座位卡显示“5号座 · 你”、角色、当前剩余BB（主）与整数筹码（辅）；实际行动者有边框强调及“待录入动作”文字，不能只靠颜色判断。全下/弃牌/空座分别标记，0余额不自动隐藏当前手玩家。筹码阶段语义遵循C02，结算时使用“手后实际余额”标签；未知终局不显示模拟结算余额为实际余额。

### 5.4 桌面与手机布局

已有左侧整块setup不再贯穿所有阶段。建桌时可展开完整表单；开桌后收为“牌桌设置/下一手设置”入口。禁止让手机用户每录一个动作都滚过桌型、奖金、全桌初始筹码和对手代号。

| 宽度 | 进行中布局 | 次要内容 |
|---|---|---|
| >=1100px | 紧凑会话栏；左侧弹性牌桌，右侧约320–360px操作/推演 | 设置按需展开；动作历史与详细分析折叠 |
| 768–1099px | 会话栏、牌桌优先；其后操作/推演按空间并排或单列 | 不采用旧的“设置+右栏在上、牌桌整行在下”顺序 |
| <768px | 状态条 → 牌桌 → 当前动作/推演摘要 | 设置、历史、帮助折叠；牌库按录入需要出现 |

手机端已选好底牌后收起完整牌库，点击底牌或需要录公共牌时再展开选择器。选择器不可遮住确认/取消，关闭后焦点回到触发控件；选牌期间不能因建议返回而重建选择器、丢失选牌或滚动位置。

小屏示意（结构约束，不要求逐字符复刻）：

```text
本桌第12手 · 翻牌                  更多
你：5号座/CO     100/200 · 每人前注25
[固定座位牌桌 · 公共牌 · 底池]
当前：3号座待录入动作
[弃牌] [过牌/跟注金额] [加注到…]
[你的局面推演摘要 / 更新状态]
动作记录（折叠）        详细分析（折叠）
```

主要点击目标至少44×44 CSS px，相邻独立动作尽量留8px间距；金额输入用适合的数字键盘但仍做完整校验。若使用底部粘性操作区，预留安全区和正文padding，320px宽及软键盘弹出时不遮住字段错误、输入框和提交按钮。折叠必须同时支持触控、键盘和明确的展开状态。

### 5.5 快速录入与推演状态

- 操作栏明确“正在录入谁的动作”，始终以合法view中的actor_seat_id为准。建议展示不自动提交动作；“建议加注”与“录入实际加注”语义分开。
- 过牌/跟注/弃牌使用现有合法动作；跟注明示金额。加注框用“加注到”，显示BB和筹码、合法最小/最大值；不能把输入当增量二次加钱。
- view验证本次动作期间，显示“正在更新局面”，暂禁依赖下一行动者的动作按钮，防止连续点击录错人；不要盲目排队多个未验证动作。
- view完成但advice仍在算时，合法的后续实际动作录入可以继续。推演不能成为记录下一动作的等待条件；新动作立刻让旧推演失效。对应请求契约见S04。
- 推演区区分“待录入底牌/轮到对手/正在推演/推演已更新/推演失败可重试”。只在轮到你且版本匹配时把结果展示为当前建议；其他阶段收为状态摘要。
- “已保存”只代表本地会话保存成功，与“推演已更新”分开。断网时可以提示计算服务不可用，但不把未验证动作当已接受，也不把旧建议继续突出显示。
- 详细范围、CFR细节、概率表与帮助默认折叠。先展示当前动作方向、金额及简短理由；缺失数据明确显示缺失，不凭空补成0。

### 5.6 手后核对与下一手

settling时，将当前动作区替换成“核对本手结束筹码”，本手牌桌保留为核对背景。全桌余额可直接编辑，确定且未变的行一次整体确认；未知行优先提示。人员调整、盲注与位置预览在同一结算流程内按需展开，普通无人变动的手不重复询问我的座位和庄位。

“确认余额，进入下一手”是结算唯一主提交按钮，复用同一事务入口。提交成功才显示新手编号和“请选择本手底牌”。最后一手结束会话时改为“确认余额，结束本桌”；手数不增加。不因展开/收起面板或切换展示单位清空编辑中的余额。

## 6. 熟人功能的关闭与保留

具体接口见contracts。必须同时满足：

1. 默认设置 `learningEnabled=false`，既有用户迁移也默认关闭，不因为旧localStorage有名字而自动开启。
2. 隐藏对手代号、学习进度、清空学习数据入口，以及建议中的VPIP/PFR、个人档案、共享样本描述；页面标题不再把对手画像作为默认卖点。
3. 页面启动、刷新、换手和结束牌局都不请求 `/api/stats/*`；包括没有名字的共享统计写入。
4. 后端建议默认只用基础范围+本手动作，不读取named/pool；仅隐藏UI不算关闭。
5. 开启后既有功能可用，名字与本次occupant绑定而非BTN等角色。位置变化不得串名；换人不继承名字。
6. 人工结束的不完整牌谱不进入学习统计；完整且已确认的牌谱用handId幂等记录。关闭时历史数据保持原样。
