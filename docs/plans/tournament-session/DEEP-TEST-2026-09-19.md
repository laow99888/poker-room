## 新发现及修复

| 编号 | 问题 | 发生场景 | 交付方案 |
|---|---|---|---|
| 77 / P2 | 清空对手余额后没有恢复估算入口 | 快捷弃牌进入核对页面，原本所有金额已预填；删除一名对手金额，提交禁用，但“未填对手沿用估算”按钮未重新出现 | 按钮始终存在，按当前草稿动态隐藏/显示；删除金额立即出现，恢复估算后可提交。自己的未知余额仍不能估算补齐 |
| 78 / P2 | 修正淘汰结果后，人员草稿冲突无法在本面板撤销 | 将某玩家余额填0、为其空座安排新人，再把原玩家余额改回正数；程序报目标座位占用，却把撤销按钮也移除了 | 候选名单验证失败时保留明确错误和“撤销本次人员变动”按钮；撤销只清人员/位置草稿，已修正金额保留，随后可正常换手 |
| 79 / P2 | 请求持续无响应时，操作长时间锁住且没有超时反馈 | 快捷弃牌、prepare创建下一手或view更新局面请求挂起，区别于立即返回503 | 快捷弃牌/prepare/view增加15秒截止，包含响应正文读取；超时释放锁、显示错误、允许重试，失败请求不推进下一手或追加动作；推演采样和advice等待策略未改 |

定位：`frontend/app.js`的`bindSettleEvents`、`renderRosterEditor`、`postTable`，以及`frontend/request-coordinator.js`的`submitView`。

复现证据：[修复前边界测试](../../screenshots/deep-1000-2026-09-19/edges-before/results.json)、[view超时修复前](../../screenshots/deep-1000-2026-09-19/view-before/results.json)。修复后：[6项边界测试](../../screenshots/deep-1000-2026-09-19/edges-final/results.json)。复现失败截图与状态均保留，未用覆盖原失败结果的方式表示修复。

## 1000手连续操作

脚本：`tests/browser/soak.e2e.mjs`。同一9人桌，默认初始筹码设为1,000,000，避免连续弃牌在长测结束前耗尽筹码。手机375px触控与1440px桌面点击交替。50手人工余额是模拟输入的现场观察结果，不是程序推演出的赢家。

| 项目 | 实际结果 |
|---|---|
| 连续完成手数 | 1000，进入第1001手 |
| 快捷弃牌 | 950手，真实quick-fold请求恰好950次 |
| 录入实际余额 | 50手 |
| 单人手前筹码校准 | 40次 |
| 刷新并逐字段比较恢复存档 | 25次 |
| 升盲 | 10次，从100/200到200/400，每人前注25 |
| 自己最终筹码 | 955,120，与独立扣费账本一致 |
| prepare请求 | 1001次，包含建桌 |
| 学习记录请求 | 0次 |
| 页面JS错误 | 0 |
| 用时 | 约12分10秒，包含点击、防连点等待、校准、刷新和截图 |
| 最近100手存档窗口 | 100条；100手时225,830字节，1000手时225,944字节 |

每手核对手号、手ID唯一性、独立计算的BTN/SB/BB轮转、自己的余额、对手估算延续、冻结历史快照、学习隔离。最近100手的平均操作周期约0.67–0.76秒，含600毫秒防连点等待，**不是胜率/决策推演耗时**。该会话未出现随手数明显增大的存档体积或持续递增的已用堆内存；不等于证明不存在内存泄漏。

长测与排查修复并行，每40手刷新加载当时版本；修复后单独跑全部新增边界用例及相关回归。最初试运行完成99手后，测试脚本在未进入结算时寻找下手盲注输入框而失败；修正脚本操作时机后，从新建桌重新完成1000手。该脚本失败保留在`soak/failure.json`，不计产品问题。
