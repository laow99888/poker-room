# 实施阶段与验收

本文件面向 GLM / Zcode 等开发执行者。以本目录完整规格为准，不能以“页面能点开”替代跨账户隔离、结算正确性及有效采样验收。

## 1. 开工前确认

读取项目约定及当前工作区，记录 HEAD、已有改动和运行服务。保留用户修改和真实数据。不得启用子代理；用户已明确希望控制额外消耗。

先产出 `IMPLEMENTATION-STATUS.md`，记录阶段状态、实际命令、测试证据、未完成项和发现的契约问题。初始所有新增验收项均为“未执行”，不能沿用旧报告里的通过数。

文档中的初始技术选择可以按证据做小范围调整，但改动金额语义、统计分母、真实/模拟边界、默认质量或权限时必须先更新相应规格及测试预期，明确原因。无法消除的产品歧义集中列出；不要每写一个函数就询问用户。

## 2. 按依赖推进的阶段

| 阶段 | 实施内容 | 完成证据及下一步门槛 |
|---|---|---|
| P0 基线与结构 | 阅读当前会话/结算/算法；建隔离测试数据；固定算法 fixture、质量定义及性能基线 | 现有测试结果、路由盘点、依赖兼容性记录、目标服务器性能测量方法；发现旧错误先记录 |
| P1 账户与数据库 | migrations、账户与会话、管理员注册开关、统一鉴权、最小账户界面 | 注册即用、关闭不影响旧用户、负面越权测试、CSRF/限流、空库迁移通过 |
| P2 服务端实战记录 | 赛事/参赛/转桌、完整手牌、结算事务、估算来源、下一手、断线恢复 | 真实/模拟分离、暂定继续、幂等、双设备冲突、未知摊牌专项通过 |
| P3 补正与历史统计 | 余额校准、历史修订、依赖过期、日期与指标、导入/导出 | 估算差额不虚构收益、统计分母正确、导入幂等、账户缓存隔离通过 |
| P4 算法与计算服务 | 有效计数、算法命名/正确性修复、热点优化、持久任务队列、取消和缓存 | 等质量基线对比、数学夹具、任务恢复和配额/旧路由封闭通过 |

P0 可先定位性能热点；不要在数据模型尚不确定时重写全部前端。P1 后旧功能临时不可调用时应给迁移提示，不能为保持演示而重新开放匿名高成本接口。

建议模块组织（可顺应仓库调整文件名）：`backend/auth/`、`backend/persistence/`、`backend/services/`、`backend/analysis_jobs/`、`migrations/`；前端将账户、历史和请求客户端从当前大文件中按职责拆出，不整体换框架。PokerKit 继续负责规则，避免重新实现完整德州规则引擎。

## 3. 固定验收夹具

每个夹具可重复初始化，并用独立预期值断言。只使用专用测试用户、专用数据库和专用浏览器上下文。

### F-A：账户隔离

总管理员 M，普通用户 A 与 B。A、B 分别拥有一个赛事、一张牌桌、一手历史、一个排队任务。记录全部 ID，故意用 A 的 Cookie 请求 B 的详情、列表筛选、修改、分析、取消、导出、导入关联和补正预览。所有越权均不成功；不能只测首页列表。

### F-B：跨手估算补正

英雄第 1 手前实测 10000，第 1 手后估算 12000，第 2 手后实测 9000；动作记录不含额外转入转出。初始两手单手净值均不可归因，只能展示区间合计 -1000。补正第 1 手后实际 11000 后，依赖一致时两手净值变为 +1000 和 -2000；有冲突则先标待核对。重复补正提交不能重复累积 -1000。

### F-C：确定与未知分开

使用旧版验收中的完整合法无摊牌牌谱作为确定样例；再用两人未知摊牌样例，改变仅引擎内部占位牌种子。无摊牌结果保持确定；未知摊牌的真实余额和赢家在两个种子下均不被自动确认。确认英雄实测余额后，允许对手显式估算进入下一手。

### F-D：统计分母

五手英雄净值分别为已确认 +100、已确认 -50、已确认 0、未知、起点估算且界面暂算 +20。盈利手牌占比为 1 / 3，不是 2 / 5、2 / 4 或 1 / 5。拿池数据独立给定，其中一手投入 100、分得边池 50，净值 -50 但 `won_any_pot=true`，验证两种指标不混用。

### F-E：日期与转桌

账户时区上海，赛事实际开始 23:55，第一手 23:58，第二手次日 00:03，之后转桌一次、同场重入一次。应为赛事 1、参赛 2、牌桌按实际创建数量、两天各一手；开始赛事只归第一天。数据库 UTC 时间不得被简单按日期截断。

### F-F：高成本与冲突采样

保存合法的 9 人宽范围场景、多人高度冲突窄范围场景、单挑 CFR 场景和多边池场景。每个包含明确质量档与固定种子。用小范围穷举作为抽样分布参考，检验有效计数、各对手顺序交换、缓存和取消行为。

## 4. 必须逐项记录的验收矩阵

| 编号 | 场景 | 预期 |

| CALC-05 | 多人平分和多个边池 | 份额、资格、返还及 EV 正确，不机械按平分 1/2 |
| CALC-06 | 替换评估库和热点优化 | 独立牌型夹具、随机对照及现有规则回归通过 |

| CALC-10 | 主权益已完成，CFR 尚运行/失败 | 分模块状态真实，整体不冒充全部完成 |

| CALC-13 | 调度/工作进程重启、租约过期、晚到旧 attempt | 恢复或明确失败；无重复有效样本、扣费、结果覆盖 |
| CALC-14 | 多块有效数不相同、取消后重新执行 | 按计数正确合并，已用 CPU 不遗漏、不重复 |
| CALC-15 | 同质量基线优化、冷/热/命中分别测量 | 报告可复现，不用减样本或缓存命中冒充优化 |
| CALC-16 | 100 在线混合请求、双计算槽满载 | 普通读写与任务提交达目标或诚实报告差距，内存和队列有界 |

## 5. 测试命令与交付证据

项目当前已有测试入口如下，实施后可增加命令但不能删除这些回归覆盖。执行前阅读 [浏览器测试说明](../../../tests/browser/README.md) 并使用隔离服务端口、数据库和浏览器用户数据目录。

```powershell
python -X utf8 _verify_all.py

node tests/browser/acceptance.e2e.mjs
node tests/browser/workspace-ui.e2e.mjs
node tests/browser/raise-units.e2e.mjs
```

新增账户/存储/任务测试接入项目现有 pytest；前端纯状态测试接入现有 Node 测试；账户登录、现场录入、历史和冲突使用真实浏览器集成测试。数据库事务与权限测试必须实际连接专用 PostgreSQL，不能全用内存假对象代替。

每一阶段只运行与改动相关的测试；最终再跑完整回归和规定的性能矩阵。旧断言与新确认的产品规则冲突时，更新其明确预期，例如未知余额可显式估算继续；同时新增反例保护未知不会变成真实值，不能简单删测试。

算法测试须采用独立预期，不允许以被测函数自己计算的结果当预期。性能脚本失败必须非零退出，测试汇总脚本必须保留子进程失败；不能以人工截图替代断言。

最终至少交付以下文件，放入本目录或其相对链接指向的固定目录：

- `IMPLEMENTATION-STATUS.md`：阶段状态和剩余问题。
- `ACCEPTANCE-RESULTS.md`：67 个验收编号与证据，标明本机/目标服务器/真机。
- `ALGORITHM-REPORT.md`：算法公式、适用边界、独立夹具和正确性结果。
- `PERFORMANCE-REPORT.md`：输入、机器、版本、有效样本、延迟分布、吞吐、容量与优化前后数据。
- `DEPLOYMENT.md`：初次部署、管理员创建、开放注册、配额、备份恢复、升级回滚。
- 锁定依赖、数据库迁移、自动化测试、用于复现的匿名 fixture 和执行脚本。

## 6. 上线阻断条件与可明确保留的后续项
